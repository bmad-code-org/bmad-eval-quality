# Epic 13 Context: the gates a consumer can run

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 12 published the values a downstream consumer reads. This epic publishes the checks it runs. Eight gates live under `scripts/` and reach no consumer, because the package's `files` list carries only `dist`, `schemas`, `corpus`, `README.md` and `LICENSE`; a consumer that wants one copies it, and the copy drifts from the day it is made. TEA is the first consumer to ask, and its Stories 4.6 and 4.7 are blocked on five of the eight. When the epic ends, a repository that has only installed `eval-quality` holds its pages, its commands, its lockfiles, its layering, its boundary and its lineage with the mechanism this repository uses on itself, configured with the consumer's own data. The epic may not ship an architecture: a gate whose rules are this repository's own decisions expressed as code stays unpublished until those decisions are data the consumer supplies. Seven configurable gates is a better outcome than eight where one imposes a foreign layer graph.

## Stories

- Story 13.1: Publish the eight gates, each configured by the consumer

## Requirements & Constraints

- **Publishability is decided and recorded per gate.** For each of the eight the story records whether it shipped, shipped with its rules as consumer data, or did not ship and why. Where a gate ships with a narrowed class set, the documentation names which classes did not survive the move and why.
- **Incremental adoption is a stated property of the configuration format.** The file carries only the gates the consumer has chosen; configuring a gate is what opts into it. A consumer adopting one gate never has to understand the other seven.
- **A gate invoked without its configuration fails naming what is missing**, with no fallback to this repository's own values. The existing `--lockfile` and `--root` flags are the precedent: both fail closed on an absent or malformed value, and `--root` refuses a root that encloses the repository.
- **Nothing in a consumer's configuration pins a version.** The lockfile-age threshold is a duration and the licence allowlist is a set of SPDX identifiers, over as many lockfiles as the consumer names.
- **The direction gate takes the consumer's trees and layer graph as data, and report-only is a declared mode.** An exit code a caller can ignore gives a green build and no report, which is the vacuous pass arriving in the one feature whose purpose is showing the size of the problem before the fix starts.
- **Every shipped gate has a compliant fixture it passes and a seeded fixture it fails.** At least one seed per gate is worded from outside the gate's trigger vocabulary, so the seed tests recall. For each gate the story names a real defect of that gate's class that the gate's own vocabulary has no word for, and seeds that one. The fixtures are the story; this is its weight-bearing criterion.
- **`npm run validate` is green at the end, and every gate this repository runs on itself runs through the published path**, so one mechanism holds both the package and its consumers.
- **New script names avoid the boundary gate's twelve forbidden `scripts` patterns**, and the exit convention is normalized across the set.

## Technical Decisions

- **Two gates cannot be published as they stand.** The direction and lineage gates import `typescript/unstable/ast` as a runtime value while `typescript` is a devDependency and `zod` is the only runtime dependency; they resolve here and fail in every consumer install, and this repository's own CI can never surface it. `typescript` becomes an optional peer dependency, and each of those two gates refuses by name when it is absent, naming the dependency and the gate that needs it.
- **Nothing under `scripts/` reaches `dist/`.** The build config includes `src` with `rootDir: "src"`; widening it shifts every emitted path and breaks `main`, `types`, `bin` and all six `exports` targets at once. The gates get their own build target or their sources move under `src/`; the story decides which and records the reasoning, because the decision outlives it.
- **The layer graph is transcribed to data first, before anything is built on it, and run against this repository's own tree.** A verdict difference against the code means the code enforced something nobody stated; that is a finding and is reported before publication continues. Agreement is recorded too, with what was compared, so a reader can tell the check ran.
- **The layering the data graph must express**: `cli -> application`, `cli -> adapters`, `application -> core`, `application -> ports`, `application -> core/schemas`, `adapters -> ports`, `adapters -> core/schemas`, `core -> core/schemas`, `ports -> core/schemas`. `core/` is one node, so imports between its submodules are same-layer and permitted. Outside itself `core/` reaches only `core/schemas`, plus two named externals: `zod` from `core/schemas` and `createHash` from `node:crypto` in the digest module. `ports/` imports `core/schemas` only. Nothing imports `cli/`.
- **The transcription came back clean on this tree and exposed two edges the `switch` hid.** One, `core-schemas -> core`, is granted by a `case` fall-through, stated by no sentence of the architecture, and exercised by no file. The table narrows it to the architecture's reading, which changes no verdict today, and records the narrowing with the citation so it reads as a correction.
- **One asymmetry is transcribed as it stands and put to the repository owner with the evidence**: the CLI's render module imports the external `zod` while the graph denies `cli -> core-schemas`. Changing it is the owner's call.
- **Exit convention**: two gates set `process.exitCode` and six call `process.exit`, which truncates a pending stdout write. The published set uses one convention.
- **Gate-by-gate shape, as read before design.** Lockfile age: generic; its flags are its whole configuration. Licences: generic mechanism with three data-shaped local policies (an SPDX allowlist, a two-policy split, one package-family tolerance). Doc invocations: generic mechanism bound through three settings derived from a package name plus one path; the only gate already running against `dist/`. Package boundary: rules as an exported data array; scanned-set composition as code encoding this repository's `files` list plus a README and LICENSE exemption. Lineage ownership: rule as data, writer allowlist derived at runtime from this package's own stage table; parameterized it becomes a generic field-ownership check, a different product, and the story decides whether that ships. Doc counts: generic mechanism whose table is the gate, with a corpus-manifest shape, an adapter-naming regex and a stamp convention that are this repository's. Doc claims: eight classes, of which citations, symbols and named codes transfer unmodified; the other five are this package's own constants wearing a table. Dependency direction: layer graph held in code in two places plus three hard-coded special cases; the largest single piece of work and the gate TEA's Story 4.7 most needs.

## Cross-Story Dependencies

- **The story ships as three contiguous pull requests, and all three are the story.** The first establishes the configuration format and the build target, since the other two cannot be written until those are settled. Order: the two gates TEA's Story 4.6 needs, then the three its Story 4.7 needs, then the three documentation gates, because 4.6 unblocks soonest on the smallest surgery and the documentation answer is the least certain. No other story is taken between them; if the run ends early, what remains is unfinished work.
- **Origin and downstream**: the story originates in TEA's Story 2.5 and blocks TEA's Stories 4.6 and 4.7. TEA is a separate repository and nothing in it is edited here.
- **Builds on Epic 12**, which published the exports a consumer reads and earned the trigger-recall lesson the seeded-fixture criterion applies: a gate's vocabulary is what its author was thinking about, so the defect it cannot describe is the one its seeds will not reach. The doc-claims gate missed a release announcement for two major versions for that reason, and both supply-chain gates passed a lockfile `resolved` substitution that kept the registry host and changed the path.
- **Precedent for shipping an executable**: the conformance suite already publishes at a documented subpath.
