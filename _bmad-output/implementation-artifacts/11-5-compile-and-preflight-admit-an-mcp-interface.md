## Intent

**Problem:** Stories 11.3 and 11.4 declare the probe semantics AD-10 requires before a kind may be opened, and two gates still refuse `mcp` on the contract side. `SUPPORTED_INTERFACE_KINDS = ['api', 'cli']` (`src/core/compile/interface-inventory.ts:31`) is module-private, so neither other gate can read it, and is checked at `:36`. `planPreflight` asserts the same fact a second time at `src/core/preflight/plan.ts:305`, because a caller can assemble a plan by hand. A third transcription of the same literal sits outside `src/`, in a table at `docs/how-to/evaluate-tool-use-behavior.md:63`, and nothing checks that it agrees with the source.

Behind those gates sit call sites that compiled only because no `mcp` contract could reach them, and the most dangerous one is invisible to the typechecker. `buildPlanIndex` sorts every resolved operation into two maps at `src/core/seal/plan-index.ts:206-242`, keyed on `iface.kind === 'cli'` at `:232`, and files everything else into the api map through `operation as Operation` at `:238`. Once Story 11.4 gives `mcp` its own operation shape, that cast hands an `McpOperation` to every consumer of `anyOperationOf` with the static type `Operation`, so `isCommandOperation` answers false, TypeScript agrees, and each downstream branch routes a tool call into the HTTP arm with no error anywhere. The cast defeats the union-widening forcing function Story 11.4 relies on.

**Approach:** Open the compile gate and the pre-flight gate on one shared literal, and restore the typechecker before touching anything it should have found. `SUPPORTED_INTERFACE_KINDS` is exported from `interface-inventory.ts` and its complement `UNSUPPORTED_INTERFACE_KINDS` is spelled beside it, both typed against `INTERFACE_KINDS` (`src/core/schemas/interface.ts:264`) and asserted to partition it, so a fifth kind has to be assigned a side. `plan.ts:305` reads that constant, which collapses two transcriptions of one fact to one. The qualification gate at `src/core/score/qualification.ts:754-763` keeps its own two-clause condition, because Story 11.6 owns `McpDefectSignature` and that gate in one diff and reading the exported constant here would open the gate as a side effect. `buildPlanIndex` gains a third map and `mcpOperationOf` beside `commandOperationOf`, and the `as Operation` cast goes, which turns every remaining mis-routed site into a typecheck failure. Then the sites the typechecker still cannot find are worked from the source: `controlInputs` (`src/core/preflight/plan.ts:233-241`) mints an empty leg over four HTTP channels, `reachability.ts:437-446` refuses the three api response channels for a command alone, and two qualification details (`src/core/score/qualification.ts:349,458`) tell a tool-use author their signature is on "an api interface". `requestOf` (`plan.ts:99-152`) gains its mcp arm and `port-messages.ts` gains the matching request member. `web` keeps firing `unsupported-interface-kind` at both gates with a message that names it correctly, and every published sentence this change makes false moves in the same diff.

## Decisions settled by construction

**Decision 1: one exported literal replaces two transcriptions, and its complement is spelled out rather than filtered.**
`SUPPORTED_INTERFACE_KINDS` (`interface-inventory.ts:31`) is module-private, and the same fact is written again as a two-clause condition at `plan.ts:305`, with a third copy in a documentation table at `docs/how-to/evaluate-tool-use-behavior.md:63`. Opening a kind touches all three, and there is no check that any of them agrees with the others. The constant is therefore exported and read by the pre-flight gate. The qualification gate at `qualification.ts:754-763` respells the same pair a fourth time and keeps its own condition here, because it reads a probe's declared kind where the other two read a contract's, and Story 11.6 lands `McpDefectSignature` and that gate in one diff; pointing it at the exported constant would open it as a side effect of a refactor. `preflight/plan.ts` already imports from `compile/sensitivity-witness.ts` at `:11-14`, so the import edge exists and `check:layers` has nothing new to judge. Moving the constant to `schemas/interface.ts` beside `INTERFACE_KINDS` was considered and turned down: which kinds the compiler admits is a compile policy, and the schema module would then state a policy that the module enforcing it does not own. `UNSUPPORTED_INTERFACE_KINDS` is spelled as its own tuple typed against `INTERFACE_KINDS`, following `pointer.ts:132-141`'s stated reason for spelling `NON_IDENTIFIER_ROOTED_CHANNELS` out, that adding a member "has to be a decision about which side of this line it falls on rather than something a filter absorbs". A test asserts the partition. Downstream consequence: Story 11.6 collapses the fourth transcription onto the same constant when it opens the qualification gate, and Story 11.9's grep for surviving `unsupported-interface-kind` claims has one source of truth to check the documentation against.

**Decision 2: `response-headers` is unreachable on an mcp operation, `response-body` and `response-status` stay reachable.**
`descriptorChannelOf` (`declared-inputs.ts:33-41`) answers `response-body` for an mcp operation after Story 11.4, and AD-19 gives every operation exactly one descriptor, so `response-body` descends through Story 11.3's descriptor as it does for an api operation. The two channels beside it are the question this decision answers, and they answer differently.

`response-headers` is unreachable. A tool result carries no header map, nothing in the MCP envelope projects onto one, and `bindings.ts:44-50` already records that `response-headers` is never a descriptor channel. Left alone, `reachability.ts` reaches its trailing `return reachable()` at `:488` for it, so an oracle pointer at a channel a tool call cannot produce compiles clean and then resolves absent at score time, which is the silent-pass failure `reachability.ts:362-368`'s own header describes: the pointer "resolves absent, every comparison over it resolves `false`, and the probe reports its defect as never triggered". So `reachability.ts:437-446` refuses it on an mcp operation with a detail naming the kind.

`response-status` stays reachable and carries `isError` as 0 or 1. That is Story 11.3's Decision 7, recorded at `11-3:191`, and Story 11.13's adapter is what performs the projection. `Observation.responseStatus` is `z.int().min(0).nullable()` (`sealed-run-record.ts:248-254`) and its description at `:253` already disclaims an HTTP reading, so the field carries the flag without a schema change. An oracle asserting that a tool did not report an error is a real check and it is the one thing the MCP envelope offers beyond the result itself, so closing the channel would throw it away. Closing it would also put the compile side and the probe side in disagreement: `foreignChannels` (`qualification.ts:148-151`) hands every non-`cli` kind the four command response channels as its foreign set, so it admits `response-status` for an `mcp` signature, and refusing the same channel at reachability would make that admission a permission nothing could use. Keeping it open leaves `foreignChannels` a boundary that fires on `stdout`, `stderr`, `exit-code`, and `artifact` with a real set on the other side of it. Downstream consequence: Story 11.13's adapter has two channels to fill and no reason to invent a header map, and Story 11.7's AD-31 grading has a decided answer for every predicate that reads a response channel.

## Design Notes

The organising idea is that this story has two halves, and only one of them is mechanical.

The mechanical half is the gates. Two of them are transcriptions of one literal, and Decision 1 collapses them to one export plus a spelled-out complement, so the next kind moves one tuple and a partition test proves nothing was left behind. The third transcription sits at `qualification.ts:755-756` and stays where it is, because collapsing it onto the same constant is how the qualification gate opens, and that gate belongs to the story that gives the probe an `mcp` signature to declare.

The other half is the class of site that keeps compiling while answering wrongly, and the ordering matters more than the count. `buildPlanIndex`'s `operation as Operation` cast at `plan-index.ts:238` is upstream of every one of them: it hands an `McpOperation` to `anyOperationOf` with the static type `Operation`, so `isCommandOperation` answers false, TypeScript agrees, and each binary ternary downstream routes a tool call into the HTTP arm without a single error. Removing the cast is what turns roughly half of those sites into typecheck failures, and it is what makes Story 11.4's union widening do the work it was chosen to do. What survives the typecheck after that is the genuinely invisible set, and it has one signature in common: each reads a field every member of the union carries and produces a value that is legal for one kind and wrong for another. `controlInputs` returns a `WitnessInputs` that parses. `reachability.ts:437-446` gates its refusal on a boolean that answers `false` for two kinds. The two qualification details resolve a ternary whose false arm says "an api interface". None of them can fail a build, and each is named in the Code Map for that reason.

Story 11.4 takes the other half of that invisible set: the three-way `declared-inputs.ts` resolution, `legalChannels`, `operationReference`, and `resolveHomeOperation`. Its Decision 7 is what makes them three-way at their one site each, so this story reads them and reports what it finds. The split is clean because Story 11.4's sites are all downstream of the operation union it declares, and this story's are all downstream of the gates it opens.

The good news, read from the source, is that Epic 9's `resolveOperations` join (`coverage/operations.ts:96-110`) already absorbed the whole coverage surface. Six of AD-20's seven rules range over that join, and every kind-shaped field they read is computed once in `declared-inputs.ts`. So Story 11.4's three helper fixes make fourteen predicates correct, and neither `relevance.ts` nor `satisfaction.ts` contains an interface-kind literal to change.
