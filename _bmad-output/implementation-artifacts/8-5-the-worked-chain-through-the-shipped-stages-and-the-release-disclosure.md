## Decisions settled by construction

**Decision 1: the AC's `npm run check:dev-corpus` names a script that does not exist; the shipped equivalent is `check:corpus`.** `package.json` has no `check:dev-corpus` entry; `check:corpus` runs `scripts/check-dev-corpus.ts` and checks the whole `corpus/` tree for orphans and drift. **Decision 2: kept as one spec despite likely exceeding the 900-1600 token guideline.** The fixed-point proof (worked chain calling shipped stages) and the release disclosure are both closing moves for the same epic-ending story epics.md itself scoped as one; splitting them would ship a corrected worked example with the surface it now proves still undisclosed, or a disclosure of a surface the worked example hasn't yet exercised end to end. Same reasoning as Stories 8.2's Decision 7, 8.3's Decision 10, and 8.4's Decision 1.

**Decision 3: `systemRecommendationNote` becomes `null`, and that is the first named byte difference.** `score()` returns `systemRecommendationNote: null` for every contract-scoring run (`score.ts:803-806`), since no declared input or caller-supplied parameter carries authored prose. The script's own 220-character sentence at `:1009-1010` therefore leaves the artifact. It is not reinstated by mutating `score()`'s product after the call: that would put back exactly the hand-set downstream value Owed item 7 exists to remove, and it would make the worked example stop being evidence of what the shipped `score` command produces. The sentence's content is preserved as a comment beside the authored record, where it explains the fixture rather than claiming to be derived output. This is the story's own answer to the frozen Intent's "byte-identical … or every difference is named with its cause".

**Decision 4: the selection prologue and the witness match stay in the script, duplicating what `score()` recomputes internally.** `WorkedExampleChain` (`:1057-1065`) publishes `selectionOf: ReadonlyMap<string, StepSelection>` and `witness: ProbeWitnessMatch`; `ScoredOutcomesAndVerdict` (`score.ts:99-114`) carries neither, and widening it would be new `src/core/` surface this story's Boundaries forbid. `tests/score/worked-example.test.ts` asserts on both. So `:1101-1126` and the `matchProbeWitness` call remain, and the file computes the selection map twice: once for its own published shape, once inside `score()`. This does not violate Owed item 7, which forbids hand-filling a value that pretends to be a reducer's output; both survivors are calls to the same shipped reference functions `score()` calls, so neither is hand-filled. Recorded rather than hidden, because a reader of the regenerated file will otherwise see the duplication and assume it was missed.

**Decision 5: the authored `PreflightVerdict` declares `fixtureDigest: digestPlaceholder(15)`.** `emit`'s `fixtureDigest` argument is currently `digestPlaceholder(15)` at the call site (`:1417`), and `runScore` sources the same argument from `preflightVerdict.fixtureDigest` (`application/score.ts:277-283`). Moving the value onto the authored verdict makes the worked chain mirror the shipped orchestration, and keeping the same placeholder value keeps the emitted byte unchanged, so this substitution contributes nothing to the diff and the two real differences stay legible. A fresh placeholder ordinal would move a byte for no gain.

**Decision 6: `waiver`, `evaluationFault`, and `corpusDigest` stay caller-supplied literals, and this satisfies the Boundaries rather than excepting them.** `waiver` and `evaluationFault` are `ScoreStage`'s two documented caller-supplied parameters (`stage-contracts.ts:78-84`), declared precisely because no declared input carries a source for either, and `runScore` passes `'none'` and `false` for them citing this script as its precedent (`application/score.ts:265-271`). `corpusDigest` is AD-11's one scoring-version input with no artifact source anywhere in the pipeline. So the Boundaries' "once a shipped stage or an authored artifact can supply it" clause is not met for any of the three, and they remain literals: the difference from the pre-change file is that they are now arguments to a shipped stage rather than fields of a hand-built assessment. `judgeConduct` is the one of the four the Intent names that genuinely stops being hand-set, since `score.ts:209-220` derives it.

**Decision 7: `src/application/index.ts` gains one more export, `RunScoreResult`.** The Code Map's CHANGELOG bullet states as fact that `runScore` is published "with its `RunScoreOptions`/`RunScoreResult` types"; at build time only `RunScoreOptions` was actually re-exported from `application/index.ts`, so `RunScoreResult` (defined in `application/score.ts`) was unreachable from `src/index.ts`. Settled by construction rather than escalated: the CHANGELOG's own claim is the intended surface, so the one-line export gap is what needed closing to make that claim true, on the same "once a shipped stage... can supply it" reasoning the other decisions here apply. Additive only, no `schemaVersion` involved.

**Decision 8: `tests/architecture/dev-corpus.test.ts`'s case 163 asserted the literal stale wording this story corrects, so its two middle patterns move to the corrected text rather than staying green by accident.** The Code Map's expectation that this test's "existing structural assertions stay green" held for six of its eight cases unchanged; case 163's own regexes matched on `Owed item 1` and `forbids hand-filling`, the exact phrases the AC requires removed from `corpus/dev/README.md`. Keeping the test as written would mean either failing it or leaving the stale phrases in the README to satisfy it, either of which defeats the AC. The two affected patterns were rewritten to assert the corrected claims (the trial reducer and score stage now shipped; the sealed run record, isolation manifest, and evaluator configuration named as `ingest`'s own inputs rather than as anyone's output) rather than deleted, so the case still enforces that the README states both absences and their current, true reason.

**Decision 9: the regenerated `evidence-artifact.json` moves a third line, `scoringVersion`, and this is the same difference as `evaluatorConfigurationDigest`, not a third one.** `emit.ts:203-217` digests the whole `scoringVersionInputs` object into `scoringVersion`, and `evaluatorConfigurationDigest` is one of that object's six members (`scoringVersionInputs.evaluatorConfigurationDigest`, the field Decision 3's neighbor names as the second real difference). Moving that one input off `digestPlaceholder(4)` deterministically moves the composite digest computed over it: `scoringVersion` carries no information the two named differences do not already carry. The frozen acceptance criterion's "the only differences are the two this story predicts" is read as two *causes*, not two *lines*: `systemRecommendationNote` and `evaluatorConfigurationDigest` are the two independent inputs this story changes, and `scoringVersion` is `evaluatorConfigurationDigest`'s own downstream consequence rather than an unexplained third cause the AC's "any third difference is investigated" clause is warning against.

## Design Notes

The core risk this story manages is silent behavioral drift: `score()` was built by lifting this exact script's own prior logic (Story 8.2), so calling it should reproduce byte-identical output — any difference is real information about where the lift diverged from the original hand-rolled path, not noise to suppress. `check:worked-example`'s byte-for-byte comparison is the mechanism that surfaces this; a difference is not a bug to hide but a fact to name in this story's Decisions, per the frozen Intent's own "byte-identical... or every difference is named with its cause."
