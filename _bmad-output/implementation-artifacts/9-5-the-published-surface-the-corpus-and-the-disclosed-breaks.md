## Intent

**Problem:** Four stories changed the language and nothing outside `src/` has caught up. The published corpus contains nineteen contracts and every one of them is an api contract, so the shape this epic exists to admit has no published example and no end-to-end evidence. Six documentation files hand-write the count "nineteen" and none is gated: `check:docs` does not scan `docs/` at all. `corpus/dev/README.md`'s "What is absent, and why" still describes the state before this epic. The worked chain (`scripts/worked-example-target.ts`, 1324 lines) proves the stage chain over an api contract and nothing else. And `CHANGELOG.md`'s `[Unreleased]` names none of it, though this epic breaks four artifacts, two code registries, a pointer grammar, and the published conformance suite.

**Approach:** Author one command contract into the dev corpus and carry it through the full chain, so the epic's claim is evidence rather than assertion. Regenerate every generated document. Correct every hand-written count at its source. Then write the disclosure the way Story 7.10 established: one `### Added` block, one `### Changed` block, a `**BREAKING**` sub-bullet per artifact naming its net move, an explicit statement of what the version number does and does not gate, and a non-comparability statement stated precisely for this epic's own mechanism, which is a value change rather than a shape change and is therefore silent where Epic 7's was loud.

## Boundaries & Constraints

**Always:**

- The corpus contract is authored where the corpus is built. `tests/coverage/fixtures/corpus.ts:510`'s `CORPUS_CONTRACTS` is the array `buildDevCorpus` reads, and `corpus/dev/README.md` is a template literal in `scripts/dev-corpus-target.ts:106+`, so every prose correction goes in the builder and is regenerated.
- Every generated document is regenerated by its own script and proved by its own check. The three are `docs/ad21-verdict-decision.generated.md`, `docs/ad31-coverage-predicates.generated.md`, and `docs/ad33-outcome-decision.generated.md`, with `generate:ad21-table` / `check:ad21-table` and their two siblings.
- The disclosure is complete over AD-11's own enumerated surface: "every interchange artifact that carries a `schemaVersion`, which is eleven of the twelve... both code registries -- AD-5's compile-time codes and AD-28's runtime faults -- and the CLI command, flag, and exit-code contract."
- Silence is stated. `CHANGELOG.md:130-133`'s "Unchanged in this release, stated so the silence is not read as an oversight" is the pattern, and every unmoved registry and command is named.
- `check:boundary` scans `corpus/` as strictly as `src/`, so the authored contract's identifiers, descriptions, and every string in it avoid all twelve forbidden strings. The adjacent repository whose contract motivated this epic carries one of them in its name and is never named in a published byte.
- AD-18 binds the published corpus as strictly as a real run: "This binds published examples and test fixtures as strictly as real runs." The authored contract names no real executable, no real path, and no real subject.

**Ask First:**

- Any `src/` behaviour change. Every one of this epic's behaviours shipped in Stories 9.1 through 9.4, and a behaviour discovered missing here is a finding against one of them rather than new scope.
- Any `schemaVersion` move. All four landed in earlier stories; this one restates them.
- `package.json`'s `version` and `src/index.ts`'s `VERSION`. Story 8.5's Never clause is the precedent: "the disclosure states the plan, the bump happens at release-cut (`npm run release:prepare`)."

**Never:**

- No hand-filled downstream value in the worked chain. Story 8.5 removed the last of them and the file's own header claims every value is stage-derived.
- No count asserted from memory. Every number in the disclosure and in the corpus prose is read off the artifact it describes at the time it is written.
- No claim that the entry criterion is met for a document outside this tree **on the strength of a corpus contract authored inside it**. The criterion's own wording is "the first time anyone authors one against the published schema without this repository's fixtures at hand", so a fixture written here cannot discharge it. It can be discharged, and the way to do it is to run the adjacent repository's own read-only check against a local build and report the reading. Step A took that reading twice: nine of nine contracts blocked on `schema-parse-failure` with 105 issue shapes before, and seven of nine compiling clean after, with the eighth blocked on `undeclared-mandatory-input` and the ninth on the artifact channel Story 9.2 mints. This story reports the same reading against the finished epic rather than a claim about a shape.
- No spine amendment and no new ADR.

## Decisions settled by construction

**Decision 1: the disclosure covers eight items and names what did not move, and the list is written down here so it is not re-derived at build time.**
Story 7.10's own record is that a recount against source found five bumps where the entry said two, so the enumeration is stated rather than trusted to memory. The eight are: the eval contract 3 → 5, in two moves (the interface-kind union and the pointer-grammar widening), where no version-3 or version-4 document parses; the sealed run record 3 → 4, where no version-3 record parses because `Observation.artifacts` is a required key; the probe 2 → 3, where no version-2 probe parses because `defectSignature` is now a union whose branches carry different keys; AD-5's registry from 23 to 25 with two codes added and three rows changed in meaning, one narrowed and two widened; `QUALIFICATION_FAILURES` from 19 to 20, which is not an AD-11 registry but is on the published surface through the score path; AD-26's channel vocabulary from seven to eight, which retypes `EvidenceChannel` in two published documents; the `EnvironmentProbePort` message shapes, which break `eval-quality/conformance` and no shipped adapter, since `src/adapters/` holds the corpus, file-system, and clock adapters only; and the corpus, which gains a member and therefore a new digest. What did not move and is named for that reason: AD-28's ten runtime fault codes, the four CLI commands with their flags and their exit-code table, the sealed evaluator brief, the isolation manifest, the evaluator configuration, the pre-flight verdict, the scoring policy, the rubric, the private artifact manifest, and the evidence artifact.

**Decision 2: the non-comparability statement is about a changed value, and saying so is the whole point of writing it separately.**
Epic 7's statement (`CHANGELOG.md:118-125`) rests on a shape change: mode entered `ScoringVersionInputs`, "a stored version names five inputs where the current one names six, and `ScoringVersionInputs` is a closed object with no legacy branch, so a five-input record surfaces as an unnamed parse failure." This epic changes no such shape. `ScoringVersionInputs` (`src/core/schemas/evidence-artifact.ts:103-110`) still declares six fields, and two of them take different values: `contractSchemaVersion` moves from 3 to 5, and `corpusDigest` moves because the corpus gained a member. So a stored scoring version parses perfectly and compares unequal, and nothing in the artifact says why. That is a weaker failure mode and a more dangerous one, because Epic 7's break announced itself and this one does not. The statement therefore says exactly that, names both changed inputs, and says recomputation is the only remedy, which is the same closing sentence Epic 7's carries. It also notes what stays true: `comparabilityKey` and `strength.comparable` are a different axis and report nothing about a version gap, which `CHANGELOG.md:122-125` already says and which is worth repeating rather than cross-referencing in a document a reader arrives at from a release page.

**Decision 3: the compile-and-seal example stays api, and the command contract ships as a corpus member rather than as a second example.**
`EXAMPLE_SEED_ID` (`dev-corpus-target.ts:69`) is fixed at `satisfied-declarations`, and `scripts/check-doc-invocations.mjs:15-18` replays every documented CLI invocation against `corpus/dev/compile-seal-example/contract.json`, so changing the example changes what every documented command is proved against. A second example directory would double that surface and double the byte gate for one story's worth of evidence. The command contract instead ships beside the nineteen, where the corpus's own purpose applies to it exactly: AD-38 calls the development corpus "visible and diagnostic", and `corpus/dev/README.md:19-21` says "every contract is published, readable, and meant to be read while writing your own", which is precisely what the first author of a command contract needs. The end-to-end evidence lives in the worked chain instead, which is where the api chain's evidence already lives. Downstream consequence: whoever adds a second compile-and-seal example inherits the invocation-replay surface, and the decision to keep one is recorded so that reader knows it was a choice.

**Decision 4: the six ungated counts get a test, and that is the only new gate this story adds.**
`check:docs` does not scan `docs/` and `check:doc-invocations` replays commands without comparing their output, so six published sentences state a fact about the corpus that nothing checks. `deferred-work.md` already records one instance of this class biting three times: a digest in `docs/tutorials/getting-started.md` went stale across three separate epics before a test was added that recomputes it. The same shape of test closes the same shape of gap here: read the corpus, count the contracts, assert each document's number. It is not a new checker script and it is not a widening of `check:docs`' roots, both of which were considered and are disproportionate to one number; `deferred-work.md`'s own closure narrative rejected a new checker script for AD-11's disclosure surface on exactly that ground. Downstream consequence: a later story adding a corpus member gets a red test naming all six files rather than a hand sweep.

**Decision 5: what this epic closes and opens in `deferred-work.md` is settled here, and one entry closes wider than it was filed.**
Closed: nothing. The census-duplication entry filed from Story 7.2 is not closed by this epic and is made worse by it, four schema changes over five test files, and it is restated with that measurement rather than left at its original wording. Opened, each with an owner: the `ObservedCallInputs` kind agreement that Story 9.4's Decision 5 routes to `ingest`, which is the first cross-artifact rule this epic adds and joins the `operationId` collision rule `sealed-run-record.ts:186-190` already routes there; the environment-probe adapter that would let a command contract be pre-flighted against a real target, which `TEST-PLAN-NEXT-STEPS.md:332-341` already records as post-v0 and which now has a second kind to serve; and whichever of Story 9.3's Decision 6 measurements shows the scripting bound miscalibrated for a command plan, if the authored contract exceeds one. That last one is conditional on a measurement this story performs, which is why it is settled here rather than pre-empted in Story 9.3.

**Decision 6: the entry criterion is reported as half met, and the half is named.**
`TEST-PLAN-NEXT-STEPS.md:322-326`'s pass condition is "one `eval-contract` document authored in the `bmad-tea` repository, against the published `eval-quality/schemas/*` subpath, compiling clean under `eval-quality compile` with no change to this package." No story in this tree can satisfy that sentence, because the document lives elsewhere and because this epic is itself a change to this package. What this epic can report is the other half the same section names: "A change needed here is the finding, and it names which part of the schema or which failure code did not carry enough information to author against." This epic is that finding, stated as eight measured items in `epic-9-context.md` and closed as five stories. So `TEST-PLAN-NEXT-STEPS.md` section 12 gains a paragraph recording the finding and its resolution, and the pass condition stays open pending a re-authoring attempt against the released surface. Claiming otherwise would be the same overclaim `deferred-work.md` records Story 8.5's first README fix making, where a corrected sentence replaced one wrong producer claim with another.

## Design Notes

The organising idea is Story 8.5's, applied to a wider surface: a worked chain that calls the shipped stages is evidence, and one that hand-composes them is a parallel derivation. This epic's claim is that a command contract is a first-class citizen of the language, and the only thing that can prove it is a command contract going through the same `compile` → `seal` → `preflight` → `ingest` → `score` → `emit` path the api contract goes through, producing bytes a byte gate compares. Everything else in this story is bookkeeping around that one proof.

The disclosure is the second half of the same idea. A break that is not disclosed is a break a caller discovers at runtime, and this epic's most dangerous break is the quietest one: a scoring version that still parses and no longer means the same thing.

## Built, and where it diverged

**Two corpus contracts rather than one**, because the two output-channel shapes are different
evidence: one describes its output on standard output and one through a file it writes.
`CORPUS_CONTRACTS` stays exactly the AD-31 cell contracts in cell order, so the check that proves it
derived rather than hand-listed keeps working, and `DEV_CORPUS_CONTRACTS` is what the published
corpus emits.

**The eval contract took one bump rather than two.** The plan gave this epic two, 3 to 4 and 4 to 5,
on the rule that each story be independently releasable. The epic ships as one release, so a version
4 that no consumer ever saw would have been churn rather than disclosure, and the single bump covers
every retype.

**The entry criterion is reported as a measured reading rather than claimed.** Before, against a
local build: nine of nine contracts `blocked` on `schema-parse-failure`, 105 issue shapes. After:
eight of nine compiling clean, zero issue shapes, and the ninth blocked on
`undeclared-mandatory-input` against a contract that declares input keys and no sensitivity witness,
which is a contract-authoring decision rather than a gap in the schema. The adjacent repository's
baseline is deliberately not rewritten from a local build; it is rewritten against the published
release, which is what makes the flip evidence rather than a self-report.
