# Epic 6 Context: ports, pre-flight, and the library and CLI surface

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 6 turns the pure core the earlier epics built into something an outside caller can adopt: the port boundary and the executable conformance suite that defines a conforming adapter, pre-flight's compile half as a plan over declared interfaces and a pure verdict over caller-supplied observations, rubric authoring rules enforced at compile time, artifact immutability and lineage as checked properties, and the library and CLI surface where every capability is reachable both ways. The constraint running through all five stories is that the package executes nothing and observes nothing on its own: impurity exists only as caller-supplied port implementations awaited in one layer, and the sole interface across which a live system is observed is a probe port the caller implements and the suite polices.

## Stories

- Story 6.1: Ports and the published conformance suite
- Story 6.2: Pre-flight as plan, observation, and pure verdict
- Story 6.3: Rubric compilation under checked rules
- Story 6.4: Artifact immutability and lineage enforcement
- Story 6.5: The library and CLI surface

## Requirements & Constraints

- The core stays pure and deterministic: no filesystem, network, clock, subprocess, or randomness, with `node:crypto` the one permitted builtin. The package never spawns a process, calls a model, drives a system under test, or invokes a judge; it depends on no provider SDK and ships no network adapter in v0.
- Every port method is asynchronous and returns a schema-valid artifact or throws a typed fault carrying a stable machine code and the artifact path that produced it. No partial success, no in-band error value, no retries or back-off; every method accepts an abort signal it must honour. The orchestration layer validates artifacts crossing a port in both directions.
- The conformance suite is published at a documented subpath, and running it is what makes an adapter conforming. Every port asserts at minimum: typed-fault throwing with a code, exactly one underlying call per invocation (which is what catches an internal retry), prompt rejection on mid-flight abort, and a schema-valid return. The probe port additionally proves default-deny including on redirect. CI runs the suite against every shipped adapter plus an in-repository probe adapter that exists only as the suite's own subject, because an unexercised suite rots.
- Probe policy is default-deny. A contract names logical interface identifiers only, never a URL, host, or port; the caller maps those to authorized targets outside the contract. Loopback, private, link-local, and metadata addresses need explicit authorization of that exact target; schemes and methods are allowlisted per target; every redirect and resolved address is revalidated; time, redirect count, and request and response bytes are capped. A denied target is a typed fault, never an observation.
- Pre-flight's verdict is pure over the returned observations and bounded to a closed list: declared interfaces present and actually matched; input sensitivity mandatory per input-bearing operation; per-run state reset verified differentially, with a repeated read as the immutability branch when no state-changing operation is declared; known-clean control behaviour; declared seeded faults being the only anomalous responses in scope, and every one observed to fire. The verdict carries the fixture digest as a required field, a failed pre-flight invalidates the run rather than becoming a contract verdict, and v0 supports the `api` interface kind while failing compilation honestly for the rest.
- Sensitivity is a declared typed witness pair plus its expected relation, evaluated over the operation's response descriptor after excluding declared volatile pointers. Whole-response inequality is explicitly the wrong predicate, and a witness resolving `insufficient-evidence` fails the pre-flight. The differential channel follows the operation's state-change marker: a path or query parameter where false, a body where true.
- Rubrics declare anchored scale levels, named failure-mode penalties, and a bounded length, and every criterion must be answerable from evidence reachable through the contract's declared interfaces. Three distinct compile-time codes cover unanchored/unbounded/missing-penalty, unreachable criterion evidence, and criteria scoring reasoning prose. Rubrics and criteria are addressable identifiers, and a zero-rubric contract compiles clean.
- An artifact is created once and never edited in place. A revision is a new artifact with a parent digest and a revision count one greater than its parent's; counts are per lineage rather than global, and the producing stage owns both fields. Same parent digest and count with different content is a conflict to surface, never to merge. Exactly one stage owns each artifact type, and the package validates a presented chain rather than tracking lineage across invocations.
- Each CLI command translates arguments into one orchestration call plus serialization and holds no validation, scoring, or policy logic. Commands are non-interactive, default to machine-readable output, take artifacts by path or stdin, write to a run-scoped directory with diagnostics on stderr, never mutate an input in place, and expose strict mode and gate promotion as explicit flags. The package declares a `bin` entry and exports the library, the generated-schema subpath, the conformance-suite subpath, and the development corpus. Nothing references BMad, TEA, or planning artifacts, and a capability reachable only through the reference client is a defect in this boundary.
- `core/` reaches at least 90 percent statement and branch coverage on in-memory fixtures and faked ports. No test does filesystem I/O outside a temporary directory or network I/O beyond a loopback fixture server it starts itself — that carve-out exists solely for the conformance suite, which cannot assert a network policy without a network. Adapters and the CLI sit outside the floor and are covered by the suite. Pre-flight's reduce consumes an observation array, so the permutation family binds to it: byte-identical output on repeat, identical outcomes under permutation.
- Secrets and subject data never enter a package artifact, published example, or test fixture, which binds the fixture server and the development corpus as strictly as a real run. Publication stays blocked by an explicit release-workflow guard.

## Technical Decisions

- The port set is closed at CorpusPort, EnvironmentProbePort, ClockPort, and FileSystemPort. There is deliberately no judge port (judging is outside the package; judge results arrive inside an ingested run record) and no digest port (digesting is deterministic and permitted in the core). **No engine-reuse seam is reserved** — a named seam with no shape invites the first team to define it unilaterally, so an engine port arrives with its first adapter or not at all.
- Stages needing external observation are pure synchronous plan-and-reduce pairs. One orchestration layer is the only place a port is awaited and holds no decision logic; both the library's public surface and the CLI sit on it, so there is one published shape rather than two.
- The two error vocabularies stay disjoint. A compile-time failure is a structural error citing a code from the generated-from registry and emits no artifact; a fault is thrown, carries a runtime-registry code, and never becomes a verdict. Rubric checks draw compile-time codes from the existing registry; port and probe failures throw.
- The library never writes to a stream: diagnostics go to a caller-supplied callback sink carrying the run identifier and emitting stage, and only the CLI adapter writes to stdout or stderr. Configuration is explicit arguments or an explicit policy artifact, with no environment-variable fallback and no implicit config-file discovery.
- Exit codes come from the closed verdict table, with fault and structural-failure codes outside the verdict range so a CI runner can distinguish a considered verdict from a crash. Verdict derivation is score-side and out of scope; the CLI wires the code contract without any story here deriving a verdict.
- Stage-one scope holds: no story touches `score`, the reference reducer, outcome-state assignment, the dominance vector, probe qualification, or detection mapping. Pre-flight's fixture digest is emitted here and consumed by a stage that does not yet exist.

## Cross-Story Dependencies

- Story 6.2 probes only through the port Story 6.1 specifies, so pre-flight cannot be built against an unproven probe contract. The in-repository probe adapter 6.1 creates is the only network-touching subject in the repository and is what makes the default-deny assertions executable.
- Story 6.2's witness relations evaluate through Epic 3's operator vocabulary and its three-valued resolution; its plan-and-reduce shape and orchestration seam come from Epic 4; the operation declarations it reads (state-change marker, response descriptor, volatile pointers, seeded faults) come from the Epic 1 contract schema.
- Story 6.3 depends on the rubric schema from Epic 1, the failure-code registry as code from Epic 4, and Epic 4's pointer resolution and reachability — criterion evidence reachability reuses that machinery rather than growing a parallel implementation.
- Story 6.4 enforces lineage fields the Epic 1 schemas already declare and the stage-ownership table the architecture fixes, adding enforcement rather than redefining either.
- Story 6.5 exports the conformance-suite subpath Story 6.1 publishes and the generated-schema subpath Epic 1 produced, and its coverage floor is measured over the whole core every prior epic built, which puts it last in the epic.
