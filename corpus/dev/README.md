# Development corpus

Twenty-four contracts and one compiled-and-sealed pair, published so an adopter can read real input to
this package without cloning the repository. Everything here is generated by
`npm run generate:dev-corpus` and checked byte for byte by `npm run check:corpus`.

## What is here

- `contracts/<contractId>.json`: twenty-four contracts. Nineteen are one per discipline rule in
  each declaration state, three describe a system under test that runs behind a command, one
  describes a tool server whose operations are the tools it publishes, and one describes a service
  behind HTTP whose plan reads a created record back at the identifier the write returned. One of
  the command contracts holds a skill responsible for a decision an agent carried out: it declares
  two behaviors with one oracle each, which is what pairs a probe with the oracle discharging the
  behavior it breaks, and it is the contract one of the three committed end-to-end chains scores a
  seeded defect against. Two of the contracts bind a step to a value the run captured from an
  earlier response, and the same two declare a fixture reset, which is what makes pre-flight plan
  its four-leg control branch over them.
  Three fail compilation by design; those ship as authored input, and `index.json` records the
  failure code each one raises. The other twenty-one are published only after this package's own
  compile stage accepts them, so every one of those is a contract the compiler admits.
- `compile-seal-example/contract.json` and `compile-seal-example/brief.json`: one contract and
  the brief this package's compile-then-seal boundary produces from it.
- `index.json`: every file above, its kind, and the digest of the exact bytes on disk.

## These contracts are visible and diagnostic

Nothing here is a holdout: every contract is published, readable, and meant to be read while writing
your own. A holdout set that measures a contract's strength is a separate thing this package does not
ship.

## What is absent

**The qualified-probe dimensions are absent.** A qualified probe is one whose qualification record and
defect signature agree with its class, and a probe corpus would carry at least one per probe class and
per `expectedClean` state. The probe schema carries both halves, and the trial reducer and the
score stage that reads it are both shipped, so an admitted probe can be scored end to end today. This
directory's own gate does not yet require one.

**Three of the four artifacts in an end-to-end example are absent here.** Such an example is a sealed
brief, a conforming sealed run record, an isolation manifest, and an evaluator configuration. The last
three are inputs the shipped `ingest` stage consumes, authored for the committed chains in
`scripts/worked-example-target.ts`, `scripts/skill-example-target.ts` and
`scripts/workflow-example-target.ts` and exercised there through `ingest`/`score`/`emit`.
Three chains are committed and the run record is the only one of the three each of them ships:
`spike-worked-example/sealed-run-record.json`,
`worked-examples/skill-defect/sealed-run-record.json` and
`worked-examples/workflow-capture/sealed-run-record.json`. The isolation manifest and the
evaluator configuration exist only as the authored values each build passes to `ingest`. This
directory ships only the compile-and-seal pair, scoped to what a corpus of contracts needs.
